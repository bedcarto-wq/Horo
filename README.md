# Horo 0.1

Локальный 2D-редактор с визуальным программированием на Python. Это первая рабочая версия школьного проекта, **не полный игровой движок**. Поведение задаёт сохранённый граф, а не встроенная демонстрация.

## Статус и требования

- Исходники: Python 3.12–3.13, PySide6 6.8.3. Целевая сборка: Windows 10/11 x64; это целевая платформа, не заявление о ручной проверке каждого выпуска.
- Сценарий Windows-сборки и GitHub Actions: `.github/workflows/check-build.yml`.
- Автоматические, ручные и EXE-проверки разделены в [docs/TESTING.md](docs/TESTING.md). Наличие исходников или зелёных тестов **не означает** завершённую ручную приёмку EXE.
- Время, физика, звук, плагины, Android и экспорт пользовательских игр отсутствуют по заданию.

## Запуск из исходников (Windows / VS Code)

Откройте корень репозитория в VS Code. В терминале PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m horo
```

Активация окружения не обязательна; поэтому политика выполнения PowerShell не мешает запуску. В VS Code выберите интерпретатор `.venv\Scripts\python.exe` через команду «Python: Select Interpreter».

Открыть проверочный проект сразу:

```powershell
.\.venv\Scripts\python.exe -m horo examples\basic\project.horo.json
```

Linux (для разработки/автоматической проверки, не вместо Windows-поставки):

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m horo
```

Для Qt могут понадобиться системные `libGL`, `libEGL`, `libxkbcommon`; в безэкранной среде задайте `QT_QPA_PLATFORM=offscreen`. Этот режим предназначен для тестов, не для обычной работы.

## Как собрать собственную первую цепочку

1. «Проект → Создать», задайте размер и выберите папку. Кириллица и пробелы допустимы. Не выбирайте папку другого проекта.
2. В ресурсах нажмите «Импорт…», выберите PNG. Ресурс скопируется в `assets/`; исходный файл затем не нужен.
3. Перетащите изображение из ресурсов на сцену. Либо нажмите «+ Объект», затем назначьте изображение в свойствах.
4. Создайте «+ Поведение». Начальный узел нажатия клавиши появляется автоматически; клавиша по умолчанию Space.
5. ПКМ на пустом месте графа → найдите «Вектор 2D» и «Переместить объект». Можно также перетащить узлы из панели категорий.
6. Вектор: X=30, Y=0. Соедините:
   - красный «Выполнить» старта → «Выполнение» перемещения;
   - синий «Этот объект» старта → «Объект» перемещения;
   - синий «Вектор» → «Смещение» перемещения.
7. Порты соединяются двумя кликами (выход справа, затем вход слева) или перетаскиванием. Треугольники — выполнение, круги — данные. Неверный тип/направление отвергается с сообщением.
8. Выберите объект. В свойствах назначьте созданное поведение. Одного существования графа в ресурсах недостаточно.
9. Сохраните. F5 открывает отдельное окно. Нажмите пробел: объект сдвинется на 30 единиц по X. Удержание не создаёт дополнительных событий.
10. F6 из редактора или закрытие игрового окна останавливает игру. Повторный запуск возвращает исходное положение. Сохранённая сцена не меняется от игры.

Если синий вход обязателен и не подключён, запуск заблокируется. Нажмите сообщение в консоли: откроется граф и выделится проблемный узел.

## Управление редактором

- Колесо: масштаб вида. Средняя кнопка: перемещение вида. Эти действия не меняют сцену/граф.
- Сцена: выберите объект, режим «Перемещение», «Масштаб» или «Поворот» и перетащите объект. Численные параметры и ширина/высота изображения доступны справа.
- Масштаб жестом меняется равномерно; раздельный X/Y — в свойствах. Нулевой масштаб запрещён. Отрицательный масштаб через свойства зеркалит изображение.
- Сетка/привязка: шаг 16 локальных единиц. «Экран проекта» возвращает вид на целевую область.
- Дерево: «+ Объект», меню «Сцена» или ПКМ. Новый объект без drop становится ребёнком выбранного. Родителя можно изменить в свойствах; локальные координаты сохраняются, поэтому мировое положение при переподчинении может измениться.
- Карточка графа: заголовок перетаскивается; `−/+` раскрывает/сворачивает поля. ПКМ по карточке: имя/удаление. Delete удаляет выбранные карточки и связи. Связь можно удалить через её ПКМ.
- Горячие клавиши редактора не действуют внутри поля ввода; используйте меню/кнопки, пока редактируете текст.
- Ctrl+Z / Ctrl+Shift+Z: история документа, максимум 100 операций. В текстовом поле — собственная история текста. Один drag — одна операция. История сбрасывается при открытии другого проекта, не сохраняется на диск.
- «Вид»: скрыть/вернуть панели и сбросить компоновку. Панели нельзя отделить в системные окна. Компоновка/положение вида между сеансами не сохраняются в 0.1.
- Дважды нажмите граф в ресурсах для открытия; ПКМ по графу — переименование. Используемый граф нельзя удалить до снятия ссылок.
- Во время игры редактор можно менять: выполняется отдельный снимок; правки применятся только при следующем запуске.

## Переменные, функции и циклы

Подробная инструкция: [docs/GRAPH.md](docs/GRAPH.md). Кратко:

- Переменные создаются в панели или кнопкой в «Прочитать/Записать переменную». Обе операции создают одну запись с ID; кнопка в карточке сразу выбирает её.
- Типы: число, текст, логическое, объект, Vector2. Неявных преобразований нет. Начальные значения чисел/логических/векторов — JSON (`0`, `true`, `[0, 0]`); текст — обычная строка; объект — ID либо пустая ссылка.
- Для функции в панели добавьте входные параметры и результаты. Вход функции и возврат получают порты с этими ID. Переименование не ломает соединения.
- «Повторить N раз → Открыть тело» открывает отдельную область. Слева показаны внешние источники. Красный порт «Тело» владельца цикла соедините с первой командой тела. Конец цепочки заканчивает итерацию автоматически. «После цикла» подключается снаружи.
- N читается один раз, должно быть целым и неотрицательным. Вложенные циклы и вызовы функции из функции в 0.1 запрещены. Поведение может ветвиться «Если», функция — без ветвления.
- Лимит: 10 000 действий/итераций/вычисленных узлов на один клавишный event (общее для всех реагирующих экземпляров). Пустой цикл тоже расходует лимит.

## Проверочные проекты

Это маленькие редактируемые модели, не полноценная игра:

| Папка | Проверка при нажатии пробела |
| --- | --- |
| `examples/basic` | +30 по X |
| `examples/counter` | первые два нажатия не двигают; начиная с третьего +20 по X; перезапуск сбрасывает счётчик |
| `examples/function_loop` | два результата функции; 3 перемещения по [15, 5], итого [45, 15] |
| `examples/loop_zero` | 0 повторений, объект неподвижен |
| `examples/loop_negative`, `loop_fractional` | понятная ошибка N, остановка игры |
| `examples/loop_continue` | 3 перемещения; continue завершает текущую итерацию |
| `examples/loop_break` | одно перемещение, затем выход из цикла |
| `examples/function_return_in_loop` | возврат из тела цикла завершает всю функцию; поведение продолжает работу |

Их можно собрать и изменить вручную в UI. Генерация этих файлов воспроизводима: `python scripts/generate_examples.py`; это не специальная ветвь выполнения.

## Тесты и Windows-сборка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Отдельно без Qt: `python -m pytest tests/test_core.py -q`.

Сборка на Windows (окружение активировано или Python 3.12 доступен как `python`):

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_windows.ps1
```

Результат: `dist/Horo-0.1.0-Windows-x64.zip`. Распакуйте **всю папку** и запустите `Horo/Horo.exe`; `_internal` обязателен. Это сборка редактора, не экспорт игры. Проекты создавайте вне папки приложения.

GitHub Actions проверяет исходники на Linux/Windows и строит Windows ZIP. Если workflow разрешён и проходит, push в `version/0.1` публикует prerelease `v0.1.0-preview`, также ZIP доступен в артефактах запуска. `BUILD.txt` внутри указывает точный commit сборки; при повторных запусках preview ZIP обновляется. Публичная версия не считается вручную принятой только из-за успешной сборки.

## Хранение, безопасность и ограничения

- `project.horo.json`: версия формата, сцена, графы, переменные. `assets/`: локальные скопированные изображения (PNG, JPEG, BMP, XPM). Ссылки относительные; переносите всю папку проекта.
- Запись JSON через временный файл + замену, повреждённый проект не подменяет открытый. Сохранение/не сохранение/отмена при закрытии и смене проекта.
- Игра не исполняет Python из проекта: нет `eval`, `exec`, pickle. Пути ресурсов не выходят за папку проекта. Начальные пустые ссылки допустимы, использование для перемещения вызывает ошибку.
- Отсутствующее изображение отображается заменой 64×64; об этом сообщает консоль. Это не скрытая «успешная» загрузка ресурса.
- Undo возвращает ссылки и значения, но **не удаляет физически импортированные файлы**: ресурсный каталог оставляет копии, чтобы не повредить пользовательские данные.
- Незавершённые графы можно сохранить, но **все** графы проекта должны пройти проверку перед запуском, даже не прикреплённые.
- Поворот/масштаб родителя учитываются. Локальный transform: `T · R · S`, мировой: `parent_world · local`. +X вправо, +Y вниз, единица — исходный пиксель, угол по часовой стрелке, начало изображения — левый верхний угол.
- Локальный лог внутренних ошибок: `%USERPROFILE%\.horo\horo.log` (на Linux `~/.horo/horo.log`). Пользовательские сообщения — в консоли редактора.
- Лимиты прототипа: проект JSON до 20 МБ, импорт картинки до 64 МБ и 16384×16384, экран 1–16384 по каждой оси, история 100 снимков, глубина дерева сцены 128 уровней. Очень крупные графы не оптимизированы.
