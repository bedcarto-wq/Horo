# Horo 0.4.0: динамика по функциям

## Границы и совместимость

Согласован вариант A: локально расширить собственную физическую подсистему, без новой зависимости и без замены Runtime/Task/Scope, модели дерева, формата 1, History и Qt UI. Это разрешённое архитектурное исключение. Старые тесты и проекты не заменены. Обратная загрузка старых проектов поддерживается; открывать новые проекты в старой версии редактора не обещается.

`PhysicsWorld.update` оставляет прежний swept-slide путь для сцен без новых возможностей. Включение гравитации, накопленной скорости, динамического/платформенного тела или односторонности включает расширенный путь. «Переместить объект» остаётся немедленным **локальным телепортом**, не переносит пассажиров и не считается физическим движением. Пересечение после телепорта диагностируется. «Двигать управляемое тело» сохраняет временную **мировую скорость только на очередной update**, последнее исполнение побеждает. Никакой автоматической гравитации старым проектам не назначается.

## Модель и единицы

`SceneNode` хранит авторские начальные значения: `mass=1`, `gravity=[0,0]`, `velocity=[0,0]`, `angular_velocity=0`, `friction=.5`, `restitution=0`, `up=[0,-1]`. Прямоугольная форма дополнительно хранит `one_way=False` и локальную `one_way_normal=[0,-1]`. Тела: неподвижное, управляемое, динамическое, движущаяся платформа.

- Расстояние: единица сцены; скорость: единица/с; гравитация: единица/с².
- Масса: условная единица массы; инерция: масса × единица².
- Импульс: масса × единица/с. Это не сила и не угловая скорость.
- Углы и угловая скорость в редакторе/графе: градусы, градусы/с, положительное вращение по часовой стрелке при Y вниз. Внутри решателя — радианы/с.
- Точка импульса и все физические векторы — **мировые**, без повторного преобразования родителем.

Сохраняются прежние ограничения: dt от 0 до .1 с, линейная скорость до 10000, размеры/зазоры не менее .5, координаты в пределах ±1e6, положительный равномерный масштаб всех физических предков. Суммарная скорость персонажа также проверяется. На слишком большом/непредставимом численном воздействии — ошибка, не скрытое ограничение значения. Платформы не вращаются автоматически.

## `rigid.mass_properties`: масса, центр и инерция

Все дочерние формы — **одно** твёрдое тело с общей массой. Площадь круга πr²; площадь многоугольника — формула ориентированной площади по исходному контуру. Масса формы `m_i = M A_i / Σ A_i`: общая поверхностная плотность. Перекрывающиеся формы считаются отдельными слоями материала, площадь пересечения учитывается повторно — это согласованное правило, не геометрическое объединение.

Для круга центр — его мировой центр, инерция относительно него `m r²/2`. Для многоугольника используются граничные интегралы площади, центра и второго момента, затем перенос оси к центру. Вычисления ведутся относительно близкой опорной точки, чтобы уменьшить потерю точности далеко от начала мира.

Общий центр: `C = Σ(m_i C_i) / M`. Общая инерция: `I = Σ(I_i + m_i |C_i-C|²)`. Например, прямоугольник 10×10 массой 2 имеет инерцию `2(10²+10²)/12 = 100/3`. Вогнутый контур интегрируется целиком; треугольники не получают независимой массы/скорости.

## `Dynamics.State` и интеграция

`PhysicsWorld` создаёт `Dynamics` внутри игрового снимка. `State` отдельно хранит мировой центр масс, инерцию, накопленную линейную/угловую скорость и гравитацию. У динамического тела ненулевые обратные масса/инерция; остальные тела для импульсного решателя имеют бесконечную массу.

Порядок `Dynamics.update`:

1. Проверить входной dt, геометрию и телепортации; запомнить геометрию начала update.
2. Выбрать адаптивный подшаг: не более 1/60 с и перемещения крайней точки не более 20% минимального фактического элемента геометрии. Скорость крайней точки учитывает `|v| + |ω|r` и запас ускорения. Минимальный размер не уменьшается по сравнению с 0.3.0. Для тонких стен подшаг получается меньше, для крупных тел — больше.
3. Выполнить поступательное движение платформ и перенос пассажиров.
4. Для персонажа/динамики: `v += g*h`. Для персонажа сложить накопленную скорость и прежнюю команду управления, выполнить старый sweep/slide; удалить только входящую в препятствие компоненту накопленной скорости.
5. Динамическое тело переместить по скорости центра и повернуть вокруг общего центра масс. `rotate` корректирует положение авторского начала объекта: смещённый центр не начинает вращаться вокруг неверной точки. Родительское преобразование учитывается один раз.
6. Построить контактные точки, решить скорости импульсами, затем отдельно исправить позиционное проникновение с учётом инерции. Позиционная коррекция не добавляет кинетической энергии.
7. Обновить опоры; после всех подшагов агрегировать контакты по парам тел и вернуть обычные события в прежнюю очередь Runtime.

`translate`/`rotate` обновляют одновременно трансформы снимка и рабочую геометрию. Полная валидация мировых границ выполняется на входе/выходе, не заменяется картинкой Qt. Нельзя обещать одинаковые последние биты при разных dt: semi-implicit Euler и последовательный решатель дают ограниченную численную погрешность.

## `rigid.features`, `Dynamics.solve`: точки, материалы и вращение

Для кругов используется точная геометрия круга и ближайшей внешней границы. Для выпуклых многоугольников — SAT и отсечение инцидентной грани боковыми плоскостями опорной грани; почти плоский контакт сохраняет две точки, каждая со своей глубиной. Для вогнутых контуров внутреннее разбиение разрешает поиск пересечения, но контакт должен принадлежать **исходной внешней границе** с подходящей нормалью. Диагонали разбиения не превращаются в стены.

В контактной точке скорость тела равна `v + ω×r`, где `r` от центра масс до точки. Нормальный импульс учитывает `1/mA + 1/mB + (rA×n)²/IA + (rB×n)²/IB`. Поэтому смещённый удар действительно создаёт вращение; это не декоративная анимация.

`solve` выполняет до 64 проходов накопленных последовательных импульсов для взаимодействующих динамических тел; для независимых контактов с бесконечной массой достаточно 16 проходов. Отскок вычисляется один раз из входящей нормальной скорости, не добавляется повторно на каждой итерации. Тангенциальный импульс ограничен кулоновским пределом `|Jt| ≤ μ Jn`.

- Материалы обоих тел: μ и e в [0,1], по умолчанию .5 и 0.
- Сочетание: `μ = sqrt(μA μB)`, `e = max(eA,eB)`.
- При нормальной скорости удара меньше 1 ед./с отскок подавляется, чтобы не создавать бесконечные микроотскоки.
- Чисто численный остаток скорости/вращения меньше 1e-5 в контакте обнуляется; это не общий коэффициент сопротивления воздуха.
- Цель позиционной коррекции 2e-6 (завершение в пределах ещё 1e-6), допуск контакта 2e-5; до 160 проходов. Большое неразрешённое пересечение вызывает диагностику, а не молчаливое проникновение.

Это учебный последовательный решатель, не гарантия промышленной устойчивости произвольно высоких стопок/произвольно сложных сцен. Очень тонкая геометрия и большие скорости требуют больше подшагов и могут замедлять редактор. Порог dt не скрывается: если реальное время между update превышает .1 с, игра выдаёт прежнюю диагностику, а не симулирует иной ход времени.

## Персонаж, опора и прыжок

`get_velocity`/`set_velocity` для персонажа читают/пишут **накопленную** скорость; не скорость ходьбы и не перенос платформой. При `g=0` и нулевой накопленной скорости старое движение работает как прежде. Ходьба по X не стирает падение по Y.

`up` — нормализованное `-gravity`, а при нулевой гравитации — явный авторский `up` (по умолчанию [0,-1]). `refresh_support` использует завершённые физические контакты с неподвижными/платформенными телами. Нормаль должна иметь скалярное произведение с `up` не меньше cos45°. Стена, потолок и динамический ящик не дают опору. При нескольких опорах выбирается наибольшее совпадение нормали, затем стабильный ID тела/формы.

`jump` при опоре задаёт компоненту скорости вдоль `up`, сохраняя касательную:

```
v_new = v - up * dot(v,up) + up * jump_speed
```

Без опоры — обычный отказ без изменения скорости, выполнение идёт дальше. Успех немедленно поглощает опору. `set_velocity` также поглощает опору при задании положительной компоненты вверх: базовый граф не получает скрытого второго прыжка. До следующего завершённого update опора не появляется повторно. Буфера, coyote time, двойного прыжка и авто-прыжка от удержания нет.

**Базовый эквивалент:** «Есть опора» → «Если» → чтение скорости и направления вверх → скалярное произведение → умножение/вычитание компоненты → добавление `up*jump_speed` → «Задать скорость». Готовая команда вызывает ту же модель скорости. Полный редактируемый пример — `24-platformer-basic-jump`.

Персонаж не толкает динамические тела: его sweep блокируется ими; в импульсном решателе он неподвижная бесконечная масса. Падающий ящик не сдвигает персонажа. На динамических телах опора/прыжок не разрешены.

## Односторонность

Поддержана **одна плоская сторона прямоугольной формы** у неподвижного тела или движущейся платформы. Локальная нормаль выбирает одну из четырёх сторон: [0,-1], [0,1], [-1,0], [1,0]; поворот формы/предков преобразует её в мир. Это не произвольная односторонность вогнутого замкнутого контура.

`plane` находит мировую нормаль/плоскость; `filter` проверяет предыдущее положение крайней точки тела и относительное движение. Тело, начавшее шаг с разрешённой обратной стороны, проходит сквозь поверхность; тело перед блокирующей плоскостью при движении к ней сталкивается. Боковые/обратные грани не становятся скрытыми стенами. Контакты отфильтрованы той же политикой, что движение и опора. Команды намеренного проваливания вниз нет: это будущий отдельный механизм временного исключения контакта.

## `platforms`: движение и пассажиры

«Двигать платформу» принимает мировую скорость только на update, последняя команда побеждает. Платформа переводится без вращения. Пассажиры — персонажи с завершённой опорой на ней, не все пересекающиеся картинки.

До движения sweep проверяет общий путь платформы и её пассажиров относительно препятствий. Берётся минимально разрешённая доля пути; **фактическое** смещение платформы и перенос персонажа одинаковы. Стена/потолок у пассажира ограничивает платформу. Урона/смерти нет. Неразрешимое исходное пересечение/сдавливание диагностируется.

После переноса персонаж отдельно выполняет ходьбу и накопленное движение. Физические тела нельзя вкладывать друг в друга, поэтому родительство не удваивает перенос. Поглощённая прыжком опора сразу исключает персонажа из пассажиров. При прыжке/сходе скорость платформы автоматически не наследуется. Динамические объекты не приклеиваются к платформе: они взаимодействуют через обычный контакт и трение.

## Каталог графа

| Чтение | Тип результата / допустимое тело |
|---|---|
| Получить скорость | Vector2; управляемое/динамическое |
| Получить гравитацию | Vector2; управляемое/динамическое |
| Получить угловую скорость | число, °/с; динамическое |
| Есть опора | bool; управляемое |
| Направление вверх | Vector2; управляемое |
| Получить массу / инерцию | число; динамическое, проверка физической модели |

| Действие | Значение / допустимое тело |
|---|---|
| Задать скорость | Vector2; управляемое/динамическое |
| Задать гравитацию | Vector2; управляемое/динамическое |
| Задать угловую скорость | число, °/с; динамическое |
| Приложить импульс | Vector2 + необязательная мировая точка, по умолчанию COM; динамическое |
| Прыгнуть | число ≥0; управляемое |
| Двигать платформу | Vector2, скорость на update; платформа |

Чтения чистые, действий не выполняют. Неподходящий тип тела — понятная ошибка узла, не тихий no-op. Математические узлы: скалярное произведение, сложение/вычитание векторов. Все используют прежние строгие порты, проверку графа, один кэш значений на действие, контекст выполнения/диагностику. События контакта продолжают приходить через обычный Task/Scope на следующем update.

## UI, сохранение и очистка

Меню «Сцена» создаёт динамическое/платформенное тело. К нему добавьте одну или несколько форм. В свойствах — масса, начальные скорости, гравитация, материалы; у прямоугольника — тип поверхности и локальная сторона. Редактирование проходит через прежние отложенные операции MainWindow и History, с проверкой/откатом и undo/redo. Формат JSON остаётся 1.

Runtime клонирует Project; изменение центра/угла/скорости во время игры не попадает в авторскую сцену. `stop` очищает состояния физики, опоры, команды платформ, контакты и контексты; Runtime также очищает задачи, ожидания, события и клавиши. Повторный запуск вновь берёт авторские значения. Ошибка физики связывается с последним командовавшим узлом, если такой контекст есть; иначе с телом/формой. Консоль редактора остаётся доступна.
