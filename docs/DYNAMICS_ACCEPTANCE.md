# Приёмка Horo 0.4.0

## Выполнено до публикации исходников

Среда: Linux, Python 3.13.14, PySide6 6.8.3, pytest 8.4.2, `QT_QPA_PLATFORM=offscreen`.

```bash
python -m pytest -q --junitxml=test-results.xml
```

**286 passed in 68.72 s**: прежние 200 тестов не изменены; добавлены 78 проверок динамики и 8 интеграционных/GUI-проверок. Тесты используют управляемое время там, где проверяется конкретный физический результат.

Проверены:

- Формулы площади, центра масс и инерции круга/прямоугольника/вогнутого контура/составного тела; смещённый центр и перекрывающиеся слои.
- Независимость ускорения от массы; индивидуальная гравитация; мировой импульс и момент импульса, вращение вокруг общего центра, преобразования родителей.
- Падение, покой, трение, отскок, контакт двумя точками, стопка из трёх тел, вогнутые/составные тела без внутренних стен разбиения.
- Быстрое движение через тонкую стену и столкновение при вращении, прежние пределы входных данных и диагностика.
- Накопленная скорость отдельно от команды управления; произвольная гравитация/направление вверх; опора до 45°; готовый и базовый прыжок, отказ в воздухе и немедленное поглощение опоры.
- Персонаж не толкает динамику ни нормальным контактом, ни трением.
- Односторонняя прямоугольная площадка: проход снизу, посадка сверху, край, повёрнутый родитель, динамическое тело, диагностика неподдерживаемого применения.
- Платформа: перенос по горизонтали/вертикали/диагонали, ходьба и прыжок, ограничение потолком, несколько опор, последняя команда, отсутствие приклеивания динамики.
- Телепорт сохраняет прежний смысл, сбрасывает устаревшую опору; импульс после телепорта использует новый мировой центр.
- Сохранение/загрузка новых начальных свойств, undo/redo в настоящих Qt-полях, типизированные карточки, контекст ошибок и очистка Runtime.
- Пять новых обычных проектов: валидация и 200 обновлений каждого, включая Space.

Это измерение на конкретной Linux-машине, **не обещание 60 FPS** и не нагрузочный тест произвольной сцены. Ранее при разработке обнаружено нарастание стоимости контактов; исправлены критерий остановки позиционного решателя и повторные вычисления геометрии. При реальном интервале более .1 с сохраняется явная диагностика — скрытого замедления времени нет.

В offscreen-режиме осмотрены снимки сцены/игры: сохранены панели и тема, видны формы и стрелка блокирующей стороны. Это **не ручной плейтест Windows EXE**.

## Windows-сборка и автоматизация

GitHub Actions запускает полный pytest на Ubuntu/Python 3.13 и Windows/Python 3.12. Windows-job зависит от обоих результатов, повторяет pytest, собирает PyInstaller onedir, включает документацию, 26 проектов, лицензии и BUILD.txt с исходным коммитом. ZIP публикуется как предварительный выпуск `v0.4.0-preview` только из ветки `version/0.4.0`.

Статус конкретного запуска смотрите в Actions. Этот документ включается в исходники **до запуска CI** и сам по себе не доказывает успешную сборку. Финальный результат CI и проверка опубликованного ZIP сообщаются отдельно. Нельзя выдавать зелёный pytest или наличие Horo.exe за ручную проверку на чистой Windows.

## Ограничения

Учебный собственный последовательный решатель, не Box2D. Нет гарантии промышленных стопок и произвольной сложности при 60 FPS. Очень тонкая геометрия, большие скорости/вращение увеличивают число адаптивных подшагов. Односторонность — одна плоская сторона прямоугольника; вращаемых платформ, продавливания вниз, coyote time, буфера прыжка и передачи скорости платформы при сходе нет. Новые подсистемы, экспорт игр и изменение дизайна UI не входят в этап.
