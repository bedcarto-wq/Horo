# Horo 0.4.1 — понятность редактора и диагностика

## Договорённости и границы

База: ветка `version/0.4.0`, коммит `53c76e7d345502ebad3485f73bb5591b0b3dd834`, совпадает с исходниками выпуска 0.4.0. До правок: **286 passed in 55.85 s** на Linux/Python 3.13.14/PySide6 6.8.3. Отсутствовавшие системные библиотеки Qt были установлены до этого повторного запуска; ошибка загрузки libGL не считалась ошибкой исходного движка.

Согласовано пользователем:

- «Вернуть значение по умолчанию» означает значение из модели, **не последнее сохранённое** и не текущее значение игрового снимка.
- Фильтры и «Показать недоступные» живут только в сеансе редактора. Системы хранения настроек не добавлено.
- Сохранён существующий предел консоли **1000 записей**. Счётчик повторов — внутри одной записи.

Python/PySide6, чёрно-синяя тема, панели, модель дерева/графов, формат 1, History и Task/Scope сохранены. Новых зависимостей и архитектурных исключений нет. Физический решатель и игровые операции не изменены. В Runtime добавлена только диагностическая метка кадра/вызова; она не участвует в планировании, значениях, времени или сериализации. Это не новый вид графа.

## 1. Откуда открыт граф

**Файлы:** `horo/ui/main.py`: `open_graph`, `refresh`, `navigate`; `horo/ui/graph.py`: `GraphEditor.build`.

Схема:

```
Кнопка объекта → open_graph(graph_id, object_id)
Ресурс         → open_graph(graph_id, None)
                           ↓
                 GraphEditor.build
                           ↓
          сцена / происхождение / вид / имя / область
```

`graph_object_id` — только UI-контекст происхождения открытия. Это не владелец ресурса и не выбранный в данный момент объект. Выбор другого объекта не подменяет происхождение уже открытого графа. Если объект удалён или больше не использует ресурс, шапка честно показывает «Ресурс графа». Прямое открытие всегда показывает ресурс, даже если сейчас привязан всего один объект.

Вид «Поведение»/«Функция» берётся из `Graph.kind`, путь тела цикла — из существующих `region_ancestors`. Подпись общего ресурса объясняет общие правки и отдельные объектные переменные. Для функции шапка перечисляет реальные `parameters`/`results` и указывает, где они доступны: выходы Вход функции, входы Вернуть результат и существующая панель сигнатуры.

`validate_project` больше не приписывает первый объект общему ресурсу: если использующих объектов несколько, диагностике не выдумывается единственный экземпляр. Ошибка при реальном выполнении, напротив, получает настоящий `Frame.object_id`.

**Как изменить:** подписи — в `GraphEditor.build`; сигнатура редактируется через прежнюю панель, а не отдельную копию параметров.

## 2. Единый источник доступности

**Файл:** `horo/validation.py`, `node_availability(graph, kind, region, adding=True)`.

Функция возвращает **None** или русское объяснение структурного запрета. Её вызывают каталог, поиск, drag/drop, `MainWindow.add_graph_node` и `validate_graph`. UI не хранит отдельную таблицу запретов.

Порядок: открыт ли граф → известен ли вид → соответствует ли виду графа → существует ли область → допустим ли старт во вложенной области → есть ли контекст для break/continue → нет ли уже входа функции при добавлении. Последняя проверка относится только к новой карточке; при валидации существующих входов прежняя проверка числа стартов работает как раньше.

Это **не проверка заполненности**. «Переместить объект» без входов можно добавить и сохранить; `validate_graph` отмечает обязательные входы на карточке и перед запуском. `read` без переменной и `call` без выбранной функции тоже не исчезают из каталога. Неподключённость не равна запрету языка.

Поиск и каталог скрывают запрещённые виды по умолчанию. Переключатель показывает серые отключённые строки, рядом написана причина, она же в tooltip. Поиск из ПКМ синхронизирует переключатель с каталогом в рамках текущего окна. Недоступные строки не перетаскиваются и не принимаются кнопкой OK. Подделанный drop или программный вызов добавления проходит ту же проверку контроллера.

**Провод:** прежний `connection_error` проверяет реальные `port_map`, типы, занятость и области. Несовместимость объясняется «Несовместимые типы. Ожидается Вектор2, получено Число». `connect` по-прежнему проверяет циклы с откатом. Отказ не добавляет связь и не создаёт History-шаг; объяснение видно над графом и в консоли. Успешная операция использует прежний `edit/History`.

**Как проверить:** в поведении найдите Вернуть результат; во внешней области — Продолжить; в функции с уже существующим входом — Вход функции. Затем добавьте разрешённый move без входов: он не запрещён, но не готов к запуску.

## 3. Карточки, порты и единицы

**Файлы:** `horo/ports.py`: `ports`, `DESCRIPTIONS`, `port_help`; `horo/ui/graph.py`: `CardItem`, `PortItem`.

Портовые ID и типы не изменены. Подсказка берёт имя, направление, тип и обязательность непосредственно из `Port`. Наличие линии определяется по реальным рёбрам графа. Данные показываются синим кружком, выполнение красным треугольником; формы и подписи работают дополнительно к цвету.

Единицы/назначение хранятся рядом с портовым каталогом, не в отдельной UI-копии языка. Примеры:

- `move.delta`: единицы сцены, **локальное** смещение в координатах родителя — прежний телепорт.
- `body_move`, `set_velocity`, `platform_move`: единицы сцены/с, **мировые** координаты; при этом временная ходьба/платформа и накопленная скорость различаются в описаниях.
- Гравитация: мировые единицы сцены/с².
- Угловая скорость: °/с, положительная по часовой стрелке при Y вниз.
- Импульс: масса × единицы сцены/с; точка — мировая позиция, без линии используется центр масс.
- Произвольный Vector2/число не объявляются автоматически мировой скоростью: единицы определяются применением.
- Пользовательские параметры функции не получают выдуманных единиц.

Порядок карточки сохранён: заголовок → подписанные порты → прежние параметры → раскрываемое «Описание» → текущие проблемы. `CardItem` получает список из **того же `validate_graph`**, а не угадывает ошибки. В заголовке виден ⚠, подробности внутри развёрнутой карточки и в tooltip. Для входа с линией добавляется «← линия»; fallback-поле объясняет, что сейчас не используется.

Раскрытие описания — UI-состояние сеанса (`description_ids`), не изменение графа и не команда undo. Старое сворачивание всей карточки остаётся прежним. Геометрия карточек/проводов обновляется существующим `build` через Qt-очередь: виджет не удаляется внутри собственного сигнала.

**Как изменить:** исправлять единицы/тексты в `ports.py`. При добавлении нового вида обязательна запись в DESCRIPTIONS; тест проверяет полноту. Правила допустимости меняются только в `node_availability`, не в описаниях.

## 4. Свойства и сброс

**Файл:** `horo/ui/main.py`: `refresh_props`, `register_reset`, `reset_property`.

Используются прежние поля QFormLayout, сгруппированные под заголовками: объект, преобразование, изображение, граф; физика/формы только у подходящих типов. Физические скорости/ускорения объясняют мировые единицы, преобразования — локальные. Неприменимая сторона обычного прямоугольника отключена с пояснением; меню открыть прикреплённый граф объясняет отсутствие поведения.

ПКМ по редактируемому свойству → **«Вернуть значение по умолчанию: …»**. Для текстовых/числовых полей сохранены стандартные пункты копирования/вставки. Значение берётся из `SceneNode`/`Transform`, не дублируется таблицей UI:

```
reset_property(object_id, 'gravity', index=0)
→ gravity.X = 0, gravity.Y не меняется
→ edit → check_structure → History.record → refresh
```

Масса → 1, μ → .5, отскок → 0, локальный X/Y/поворот → 0, масштаб → 1. Имя по умолчанию модели — «Объект»; это не автоматически подобранное имя при создании. Сброс размера изображения возвращает соответствующий масштаб к 1, то есть естественный размер изображения. У формы можно сбросить её данные, а не удалять всю форму.

Ожидающие отложенные изменения сначала фиксируются через `flush_edits`; сам сброс из меню ставится в Qt-очередь после закрытия меню. Поэтому поздний editingFinished не возвращает введённое значение поверх дефолта, а удаление виджета при refresh не происходит внутри его меню. Закрывшееся меню удаляется, не накапливается до выхода.

Только выбранное поле/компонента меняется. Например, масштаб X не исправляет Y заодно. Если одиночный сброс нарушает прежнее структурное правило (например, равномерность физического масштаба), транзакция откатывается с объяснением; скрытого изменения соседнего свойства нет. Нет разрушительной миграции. Runtime-снимок не читается. Undo возвращает прежний авторский документ, redo повторяет сброс.

## 5. Состояние редактора

**Файл:** `horo/ui/main.py`: `sync_state`, `run_game`, `game_failed`, `game_finished`, `stop_game`.

Постоянная подпись справа в строке состояния:

- **Редактирование** — нет работающего игрового снимка и актуальной ошибки запуска.
- **Игра запущена** — существует `GameWindow`, его `runtime.running` истинно.
- **Остановлено из-за ошибки** — последний запуск/его выполнение завершилось ошибкой. Новый исправный запуск очищает признак; открытие другого проекта тоже.

Никакого второго игрового автомата нет. Факт работы берётся из Runtime; `last_run_error` хранит только причину остановки, которую `running=False` сам по себе не различает. Проверка проекта до создания окна также может остановить запуск. Stop без игрового окна отключён с причиной; Run во время работы по-прежнему переводит к уже открытому окну. Редактирование во время игры **не запрещено**: оно, как прежде, меняет только авторский проект для следующего запуска.

Экспортного состояния нет: экспорт не входит в 0.4.1. Новое состояние в будущем можно отразить через этот же метод после реализации соответствующей функции.

## 6. Консоль, источники и приватность

**Файлы:** `horo/ui/console.py`, `horo/errors.py`, диагностические строки в `horo/runtime.py`; переходы в `horo/ui/main.py`.

`ConsolePanel` — локальная оболочка прежнего QListWidget: фильтры Ошибка/Предупреждение/Сообщение, очистка, список, адресные переходы, раскрываемые безопасные технические сведения, копирование по явной кнопке. `MainWindow.console` остаётся ссылкой на список для прежней интеграции. Ошибки валидации/Runtime — error; отсутствующий ресурс/отказы UI — warning; сохранение/старт/импорт — info. Действия, которые не имеют источника, не получают выдуманный graph/object/shape ID.

Технические сведения — текст сообщения, реальные имена/ID источников, ожидаемый тип и непрозрачная метка выполнения. **Значения входов, аргументов и переменных не выгружаются автоматически**. `Diagnostic.describe` оставлен совместимым для внутреннего использования; консоль всегда вызывает безопасный режим и хранит копию без `received`. Copy копирует этот же безопасный текст, не скрытый дамп. Системный лог непредвиденного исключения сохраняет расположения кадров Python, но не произвольный текст исключения с возможным вводом пользователя. Имя/ID графа и объекта остаются видны как необходимые источники.

Ключ совпадения — SHA-256 точного набора: уровень, сообщение, graph/node/object/shape, expected/received, invocation. В ключе не хранится открытый полученный пользовательский текст. Разные сообщения/объекты/формы/вызовы не склеиваются. Это не сравнение только по видимому короткому заголовку.

В Runtime отдельный диагностический счётчик выдаёт `session_uuid/frame_number`; вложенная функция получает свою метку. Существующий счётчик задач и порядок обслуживания **не затронуты**. Диагностика вне конкретного кадра использует сессию. Проверки до запуска ещё не являются вызовом Runtime и группируются по своему структурному источнику.

При точном повторе увеличивается счётчик, а не добавляется строка; после 1000 разных записей удаляется наименее недавно использованная запись. Значения не записываются в проект, настройки тоже. Runtime не пишет сообщение каждый update: сообщений из физического шага/цикла «заодно» не добавлено.

Переход нажатием сообщения сохраняет прежний приоритет графового узла; отдельные кнопки позволяют выбрать граф, объект или форму. Если ID отсутствует, кнопка отключена с причиной. Если ID был, но источник уже удалён, появляется объяснение вместо обращения к отсутствующему виджету. Copy работает без VS Code. Очистка удаляет и строки, и внутренний индекс группировки.

## 7. Как запустить, проверить и менять

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m horo examples\27-editor-clarity\project.horo.json
.\.venv\Scripts\python.exe -m pytest -q --junitxml=test-results.xml
.\scripts\build_windows.ps1
```

VS Code: открыть корень репозитория, выбрать интерпретатор `.venv\Scripts\python.exe`. Консольные технические сведения доступны и без VS Code.

Новый небольшой проект `27-editor-clarity` содержит два экземпляра общего поведения, функцию с параметрами/результатами и вложенное тело цикла. В папке есть пошаговый README. Space сдвигает оба объекта на (45,15). Для диагностики намеренно добавляйте неполный узел/неверную связь и затем отменяйте: поставленный проект изначально корректен, не заблокирован тестовой ошибкой.

Автотесты — `tests/test_editor_clarity.py` и весь прежний набор. Чек-лист и честное разделение проверок — `EDITOR_CLARITY_ACCEPTANCE.md`. Windows ZIP — **редактор**, не экспортированная игра. Распаковывать всю папку. К исходному коммиту сборку привязывает BUILD.txt.
