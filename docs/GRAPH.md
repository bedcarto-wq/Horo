# Базовые графы Horo: цепочки этапа 1

> Этот документ описывает базовые проверочные графы. Новые возможности 0.2.0 и снятые локальные ограничения — в TIME_GRAPH.md и TIME_RUNTIME.md.

## Общие правила

В ресурсах существуют два типа: поведение и функция. Поведение прикрепляется к сценическому объекту; функция вызывается поведением. В 0.1 был один старт на граф; 0.2.0 поддерживает несколько событий поведения. Красный поток определяет порядок действий, синий — значения, которые запрашиваются при выполнении действия. Чистая синяя карточка сама по себе ничего не делает.

Имена сущностей — подписи; ID — ссылки. Переменные и параметры переименовываются двойным щелчком в панели справа. Тип существующей записи в 0.1 намеренно нельзя поменять одной правкой: создайте новую типизированную запись и явно переподключите программу. Удаление используемой записи сообщает об ошибках и может быть отменено.

Пустое поле object — пустая ссылка, **не** «этот объект». Контекст этого объекта выдаёт старт. Единственное явно помеченное исключение/default — объектная переменная поведения: без отдельного входа объекта она работает с контекстом поведения.

## A. Счётчик и условие

1. Создайте локальный проект и изображение. В ресурсах создайте поведение «После третьего нажатия», назначьте его изображению.
2. Справа откройте панель «Переменные и сигнатура функции», создайте «Нажатия»: тип Число, область Объекта, начальное значение `0`.
3. Добавьте карточки: «Прочитать переменную», «Число» (1), «Сложить числа», «Записать переменную», «Число» (2), «Больше», «Если», «Вектор 2D» ([20,0]), «Переместить объект».
4. В read/write выберите **одну и ту же** переменную «Нажатия». Можно вместо шага 2 создать её кнопкой в read; затем выбрать существующую в write, не создавать дубликат.
5. Соедините синие данные:

| Откуда | Куда |
| --- | --- |
| read.Значение | add.A |
| Число 1.Значение | add.B |
| add.Сумма | write.Нажатия |
| read.Значение | greater.A |
| Число 2.Значение | greater.B |
| greater.A > B | if.Условие |
| key.Этот объект | move.Объект |
| vector.Вектор | move.Смещение |

6. Соедините красное выполнение:

```text
key.Выполнить → write.Выполнение
write.Далее → if.Выполнение
if.Да → move.Выполнение
```

Оставьте «Нет» неподключённым: цепочка заканчивается. Это не ошибка, потому что выход выполнения не обязателен.

7. Сохраните, запустите. На первых двух нажатиях координаты не меняются. На третьем перемещение +20; на каждом следующем тоже +20. Остановите/запустите: первые два нажатия вновь не двигают.

**Почему чтение одно, а значения актуальны:** read — чистая карточка. Когда write запрашивает add, read возвращает старый счётчик. После записи if начинает другое действие с новым кешем; его greater читает уже увеличенный счётчик.

Проверка типов: попробуйте соединить выход «Число» с «Условием» if. Такое соединение запрещено: требуется bool. Проверка undo: удалите write, отмените; его ID, параметры и обе связи должны вернуться.

## Б. Функция с двумя результатами и цикл

### Функция

1. Создайте граф-функцию «Получить смещение». Вход функции появляется автоматически.
2. В панели справа нажмите «+ Вход» дважды: «Число» типа Число; «Вектор» типа Вектор2.
3. «+ Результат» дважды: «Смещение» типа Вектор2; «Повторы» типа Число.
4. Добавьте «Вернуть результат».
5. Красное: entry.Выполнить → return.Выполнение.
6. Синее: entry.Вектор → return.Смещение; entry.Число → return.Повторы.

Функция намеренно просто возвращает аргументы под именами результатов; это проверяет передачу/типы/несколько выходов, а не сложную арифметику. Впоследствии её содержимое можно изменить, не меняя сам механизм вызова.

### Поведение

1. Создайте поведение, назначьте изображению. Добавьте Число=3, Вектор2=[15,5], «Вызвать функцию», «Повторить N раз».
2. В call выберите «Получить смещение». Появятся типизированные входы/выходы по сигнатуре.
3. Синее: number → call.Число; vector → call.Вектор; call.Повторы → repeat.N.
4. Красное: key.Выполнить → call.Выполнение; call.Далее → repeat.Выполнение.
5. В repeat нажмите «Открыть тело». Это **отдельная область модели**, не прямоугольник на общем холсте.
6. Добавьте «Переместить объект» в тело. У владельца repeat слева активен «Тело». Соедините repeat.Тело → move.Выполнение.
7. Внешние карточки слева не редактируются в теле: key.Этот объект → move.Объект; call.Смещение → move.Смещение.
8. Оставьте move.Далее неподключённым — конец итерации. Никакой обратной линии к repeat делать не надо.
9. Вернитесь «← Внешний граф», сохраните, запустите. Одно нажатие даёт 3×[15,5] = [45,15].

Оба результата должны использоваться: один задаёт N, другой — смещение. Проверка «результат до call»: обойдите красный call и сразу идите к repeat — runtime остановится при запросе неподготовленного результата.

### Варианты цикла

- N=0: функция всё ещё вызывается, но тело repeat не выполняется.
- N=-1 или 1.5: понятная ошибка на repeat, игра остановлена, редактор открыт.
- «Продолжить»: добавьте карточку в тело после move. Она завершает текущую итерацию; следующие начинаются. При N=3 итог остаётся [45,15].
- «Прервать цикл»: добавьте после move. При N=3 выполнится только первое перемещение [15,5], затем пойдёт внешнее продолжение repeat.
- Return из цикла **функции**: в функции вместо прямого entry→return создайте repeat; entry.Число → N; перенесите return в тело (в 0.1 проще удалить старый и создать его в области тела), body→return. Входные данные entry доступны слева. При N>0 первый return завершает **весь вызов**, не только итерацию. При N=0 функция с результатами завершится без return и выдаст ошибку.

## Области и ограничения

- N вычисляется только при входе в repeat, не перечитывается после каждой итерации.
- Одна карточка принадлежит одной области через ID. Внешнее продолжение не может одновременно быть телом.
- Данные корня доступны телу; данные из тела не экспортируются самовольно наружу. Для изменяемого состояния используйте переменную с согласованной областью.
- В 0.2.0 тело repeat/while допускает вложенные циклы в той же модели region; обратные провода всё ещё запрещены.
- В 0.2.0 функции могут содержать If, вложенные calls, ожидания и ветки; стартовых событий внутри функции нет.
- Чистые значения имеют один снимок на действие; два действия — два кеша. Данные переменных изменяются только красным write.
- Переданный object должен быть действительным ID либо явно пустой ссылкой; пустой объект нельзя перемещать.
- Перезапуск игры сбрасывает переменные игры и объектов к начальным; каждый event/вызов создаёт новые run-данные.
- Незаконченный граф сохраняется, но запуск валидирует **все** графы. Лимит 10 000 шагов считает даже пустые итерации.

После изменения сохраните и заново откройте проект: порты, параметры, результаты, переменные, ID, область цикла и положения карточек должны сохраниться. Физический перенос всей папки проекта не должен ломать изображение.
