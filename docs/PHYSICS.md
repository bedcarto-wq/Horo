# Этап 3: управление и столкновения (0.3.0)

## Что согласовано и реализовано

Python/PySide6, дерево SceneNode, Project, JSON format_version=1, History и Task/Scope сохранены. Физика — отдельное дополнение к Runtime, не новый движок исполнения. Зависимостей не добавлено. Обычные объекты и старые проекты без физических тел не получают физических ограничений dt/масштаба.

Типы дерева: `static_body` (неподвижное), `controlled_body` (управляемое), дочерние `rect_shape`, `circle_shape`, `polygon_shape`. Формы — обычные узлы с прежними ID, родителем и Transform; не компоненты. Формы должны быть непосредственными детьми тела. Вложенные тела запрещены. Несколько форм одного тела могут перекрываться и образуют единый коллайдер. Перекрывающиеся отдельные тела, включая неподвижные, считаются ошибкой начальной сцены: для пересекающихся стен используйте формы одного составного тела.

### Ввод и движение

- `Клавиша удерживается` (`held`) — чистое Логическое значение. Клавиша настраивается в карточке.
- `Направление по клавишам` (`direction`) — сырой Вектор2: right-left, down-up. Каждая из четырёх клавиш настраивается. Противоположные взаимно компенсируются. WASD — значения по умолчанию, не игровой режим.
- `Нормализовать вектор` (`normalize`) — направление длиной 1; ноль остаётся нулём. Сначала делим на максимальную компоненту, чтобы не получить переполнение на больших конечных значениях.
- `Умножить вектор на число` (`vector_scale`) — строгие типы vector и number, без преобразования строк.
- `Двигать управляемое тело` (`body_move`) — записывает **мировую скорость в единицах/с**. Само перемещение происходит один раз в физической фазе. Последняя команда телу до этой фазы побеждает; скорости не суммируются. В следующем обновлении без новой команды тело стоит. Поэтому граф управления обычно начинается с «Каждый кадр». Команда из обработчика клавиши действует только на ближайшее обновление.
- `Начало контакта` / `Конец контакта` — старты существующего поведения. Выходы: этот объект, второе тело, время сеанса. «Второе тело» — ID исходного тела, не ID его формы.

**Старый `Переместить объект` не изменён:** сразу прибавляет локальное смещение, игнорируя столкновения. Если после такой телепортации тела проникли друг в друга, следующая физическая фаза останавливает игру. Это не выталкивание и не превращение старой команды в физическое движение. Положение сразу после нового узла скорости ещё не изменено: движение отложено до физической фазы.

## Фазы одного обновления

1. Прежний Runtime сбрасывает общий бюджет, будит созревшие ожидания.
2. В тот же FIFO добавляются события контакта, обнаруженные прошлым обновлением, затем события «Каждый кадр».
3. Прежний `_drain` выполняет задачи. Движение тела пока только записывает скорость.
4. Если игра ещё работает: проверяются формы и положения; решатель обрабатывает команды с текущим dt.
5. После движения определяются пары контактов. Начала/концы сохраняются до следующего обновления, без рекурсивного выполнения из геометрии.
6. GameWindow показывает snapshot Runtime, как прежде.

Задачи контактов используют тот же Task/Scope, общий лимит шагов, предел задач, ожидания и новые изолированные run-переменные. Объектные/игровые переменные работают как раньше. Остановка очищает задачи, команды, held-клавиши и контакты. Новый Runtime снова клонирует авторскую сцену.

Управляемые тела блокируют друг друга без толкания. Порядок — порядок объектов сохранённого проекта. Это детерминированно, но при встречном движении даёт приоритет первому: симметричного динамического решателя здесь нет.

## Геометрия и математика

### Координаты

Прежний Transform строит матрицу `T * R * S`, Project.world_matrix умножает цепочку родителей один раз. `world_shapes` применяет эту матрицу к локальным точкам формы. Прямоугольник центрирован в (0,0), ширина и высота задают его границы. Радиус круга умножается на общий положительный равномерный масштаб. Контур хранится в локальных координатах формы.

Для скорости v и длительности dt:

```
d = v * dt
```

dt применяется **только здесь**, не умножайте скорость на delta ещё и в графе. Чтобы записать мировое перемещение в локальную позицию тела, `_translate` умножает d на обратную линейную часть матрицы родителя. Поэтому повёрнутый родитель не поворачивает выбранное мировое направление повторно.

Ограничение физической цепочки: sx=sy>0 у формы, тела и всех родителей. Отрицательные и неравномерные масштабы дают ошибку с указанием формы; круг никогда не выдаётся за эллипс с круговым коллайдером. Обычные объекты без физики сохраняют прежнюю поддержку масштаба.

### Контуры и триангуляция

`validate_polygon` проверяет конечность, разные вершины, ненулевую площадь, пересечения, обратные/повторные рёбра и слишком маленькие детали. Авторский список не меняется. Внутренняя копия ориентируется против часовой стрелки в математическом смысле координат. Метод `triangulate` последовательно отсекает «уши»: выпуклая тройка вершин, внутрь которой не попали другие вершины. Удаление тройки уменьшает внутренний контур, пока не остаётся треугольник. Исходный редактируемый контур и ID сохраняются.

Важное уточнение реализации: треугольники нужны для проверки **проникновения** через SAT (теорему о разделяющей оси). Непрерывное движение проверяется непосредственно по внешним рёбрам/вершинам исходных контуров, а не по внутренним рёбрам треугольников. Это точная проверка поступательного движения геометрических признаков, не дискретные подшаги. Такой выбор исключает внутренние швы из нормалей скольжения; новая библиотека или замена Runtime для этого не нужны.

### Непрерывная проверка

`Shape` — только вычисленная мировая геометрия: points для контура либо center/radius для круга. `bounds` строит ограничивающий прямоугольник. Перед дорогой проверкой `sweep` проверяет прямоугольник всего пройденного пути.

- Контур/контур: движущиеся вершины против неподвижных рёбер, затем неподвижные вершины относительно движущихся рёбер. Учитываются обе стороны, поэтому нельзя пропустить столкновение широкой грани с углом.
- Круг/контур: центр движется против отодвинутых на радиус рёбер и окружностей вокруг вершин.
- Круг/круг: относительный луч против окружности с суммой радиусов.
- Контур/круг: та же проверка с обратным относительным движением и обратной нормалью.

Для вершины p, движения d, внешней единичной нормали n и точки ребра a момент встречи вычисляется из:

```
dot(p + t*d - a, n) = offset
t = (dot(a-p, n) + offset) / dot(d,n)
```

Нужны приближение к поверхности (`dot(d,n)<0`), t в [0,1] и попадание на конечный отрезок. Для круга/вершины решается квадратное уравнение длины относительного вектора до радиуса. Для контуров отдельно отбрасываются касательные совпадения концов рёбер: после точного кандидата проверяется наличие входа в материал на расстоянии 0.0001 вдоль пути. Эта численная проба только классифицирует кандидат; тело не перемещается дискретными шагами. Она меньше минимальной поддержанной детали 0.5 и исключает ложную стену на стыке составных форм. Выбирается самый ранний допустимый момент. Это позволяет заметить стену толщиной 0.5 даже когда перемещение за кадр больше её толщины.

### Скольжение

`PhysicsWorld.move`:

1. Находит самое раннее столкновение всех форм тела со всеми формами других тел.
2. Перемещает тело к этому моменту с малым защитным зазором.
3. Собирает нормали одновременных упоров.
4. Из оставшегося движения убирает компоненты, направленные внутрь препятствий:

```
inward = dot(remainder, normal)
if inward < 0:
    remainder -= normal * inward
```

5. Повторяет поиск на оставшемся касательном движении. При противоречащих ограничениях угла остаток блокируется. Выход наружу от стены разрешён в следующем обновлении.

Это не моделирование массы, трения или импульса. Нет гравитации, динамических тел и прыжков. Не более 16 последовательных столкновений на одно перемещение; если ненулевой остаток не разрешён, выдаётся ошибка, а не молчаливое усечение движения.

### Контакты

После движения `distance` определяет расстояние по исходным границам. Контакт — не только положительная площадь пересечения: касание с нулевой площадью также считается.

- новый контакт: расстояние ≤ `ENTER = 0.00001`;
- уже существующий контакт сохраняется до `LEAVE = 0.00002`;
- геометрический зазор/допуск вычислений `EPS = 0.000001`.

Разные пороги входа/выхода — гистерезис, защищающий от дребезга. Пара хранится как отсортированные **ID тел**. Любая пара форм подтверждает контакт тел, а конец появляется только после исчезновения всех пар форм. Переход между соседними формами одного тела не создаёт новое начало. Если за одно обновление подтверждён кратковременный swept-упор, но тело успело соскользнуть за край, в следующем обновлении доставляются одно начало и один конец этого краткого контакта.

При удалении тела выживший получает конец после следующего обнаружения; удалённому ничего не доставляется. ID удалённого «второго тела» может быть недействительным: попытка использовать его как живой объект даёт обычную ошибку ссылки. Публичного узла удаления в этом этапе нет; безопасность удаления проверяется тестовым изменением Runtime-сцены во время обработки события. Stop из обработчика очищает все дальнейшие события.

## Редактор форм

1. `Сцена → Управляемое тело` или `Неподвижное тело`.
2. Выберите тело и добавьте дочернюю форму через меню `Сцена`.
3. У прямоугольника задайте ширину/высоту, у круга радиус в свойствах. Положение и поворот — прежние локальные Transform.
4. Для многоугольника нажмите «Нарисовать заново» или «Редактировать точки».
5. Новый контур: клики ставят вершины; Enter либо `Сцена → Завершить контур` замыкает его. Escape либо «Отменить черновик» отменяет незаписанный черновик.
6. Существующий контур: перетаскивайте маркеры; Shift+клик рядом с ребром вставляет вершину; выберите маркер и Delete удаляет его.

`ContourTool` хранит отдельный список точек вне Project. Пока мышь движется, меняется только черновик. После отпускания валидный контур передаётся сигналом в `MainWindow.commit_contour` и через прежний deferred_edit/History становится одной операцией undo. Неверный контур остаётся черновиком, а сохранённая валидная форма не меняется. Новый контур записывается целиком после Enter. Escape не отменяет уже записанные валидные перетаскивания: для этого Ctrl+Z. Undo/redo закрывают текущий черновик и восстанавливают прежние ID/точки через обычный снимок.

Контур/ручки рисуются поверх SceneCanvas, в координатах прежнего QGraphicsItem формы. Масштаб вида не входит в геометрию; размер маркеров задан в экранных пикселях. Сетка и привязка 16 продолжают работать. Положение родителя не прибавляется повторно.

При тестировании обнаружен нативный сбой PySide6 при очистке дерева после выбора через QTreeWidgetItemIterator. Локальное исправление: выбирать элемент по существующей таблице ID → QTreeWidgetItem, которую строит refresh. Модель дерева и панели не менялись; добавлен регрессионный тест многократного создания/выбора/undo/удаления составного тела.

## Проверенный поднабор и явные ограничения

- dt физической сцены: от 0 до 0.1 с включительно. Большая задержка выдаёт диагностику, не скрытое обрезание времени. Если окно/ОС задержало кадр больше этого предела, игру нужно перезапустить; автоматическая пауза при потере фокуса не добавлялась.
- Длина скорости ≤10000 ед./с. Конечные мировые границы форм внутри ±1000000.
- Минимальный мировой диаметр круга/размер прямоугольника/деталь контура — 0.5. Локальные размеры также не меньше этого минимума (радиус ≥0.25). Проверка контуров консервативна: слишком близкие несмежные рёбра запрещены, даже если очень сложный контур мог бы быть математически допустим.
- Только положительный равномерный масштаб всей физической цепочки. Без отверстий, самопересечений и кривых; круг — отдельный примитив. Пиксельной физики по прозрачности нет.
- Движение непрерывное **поступательное**. Анимация вращения/масштаба и насильственное изменение Transform — перестановка геометрии, не swept-вращение. Если это создаёт проникновение, следующая проверка останавливает игру.
- На патологически сложном угле возможна явная ошибка сходимости. Универсальная точность при произвольной геометрии/скорости не заявляется.
- Полный перебор пар с AABB-отсечением рассчитан на небольшой школьный проект, не на тысячи тел. Пространственный индекс не внедрялся без необходимости.

### Что менять самостоятельно

- Клавиши — в карточках held/direction; скорость — в узле «Число», подключённом к vector_scale.
- Формы/положение — через дерево и свойства; контур — на сцене.
- Пороги касания — ENTER/LEAVE в geometry.py; после изменения прогоните тесты контакта и стыков.
- Предел скорости/dt — MAX_SPEED/MAX_DT в physics.py. Простое увеличение чисел не доказывает работоспособность нового диапазона: сначала добавьте граничные тесты.
- Новый чистый узел — LABELS/CATEGORIES/ports, затем Runtime.evaluate, карточка при необходимости и тесты строгих типов.

## Запуск и проверка

Из VS Code откройте папку репозитория, выберите интерпретатор `.venv`, затем терминал:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m horo
.\.venv\Scripts\python.exe -m pytest -q
powershell -ExecutionPolicy Bypass -File scripts/build_windows.ps1
```

Примеры:

- `physics_playground`: WASD, нормализованная скорость 180, прямые/круглые/вогнутые/повёрнутые препятствия, второе управляемое тело и счётчики начал/концов контактов.
- `physics_thin_wall`: D направо, скорость 10000, неподвижная стена толщиной 0.5. Тело останавливается перед ней.
- `physics_custom_input`: движение вправо на Right через held → if → run-переменную → vector → normalize → vector_scale. Узла direction нет: ввод не зашит в движок.

Счётчики — обычные объектные переменные Runtime, их удобно проверять в тестах/отладчике. В этой версии нет Print и отдельного HUD для вывода значений; не путайте начальное значение свойства редактора с текущим значением Runtime.

Распакуйте весь Windows ZIP и запускайте `Horo/Horo.exe`, не отделяя EXE от `_internal`. Сборка редактора не является экспортом пользовательской игры.
