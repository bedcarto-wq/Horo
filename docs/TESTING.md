# Проверки и приёмка 0.1

## Зафиксированная локальная проверка

Среда: Amazon Linux 2023 x64, Python 3.13, PySide6 6.8.3, pytest 8.x. Qt: `QT_QPA_PLATFORM=offscreen`; системные GL/EGL/xkbcommon установлены для запуска Qt. Дата подготовки: 14 октября 2026.

Команда:

```bash
QT_QPA_PLATFORM=offscreen python -m pytest -q
```

**Результат локального запуска: 68 passed.** Это автоматические проверки исходников, не ручная Windows-приёмка. Тесты не требуют показывать GUI пользователю.

### Что покрыто автоматически

- Составные локальные/мировые преобразования; перемещение родителя; размер экрана не меняет transform.
- Полный JSON round trip базового графа, счётчика и функции/цикла; кириллица/пробелы в пути.
- Копирование PNG, удаление исходного изображения, физический перенос папки проекта, относительные пути и запрет выхода за корень.
- Типы/направление портов, единственный источник входа, единственное красное продолжение, несколько синих потребителей.
- Циклы данных/выполнения, висячие ссылки, удаление узла/области вместе со связями.
- Клавиша → Vector2 → движение; неприменимость автоповтора, reset и отсутствие изменения авторской модели.
- Один граф на двух объектах: отдельные контексты; каждое назначение независимо реагирует на свою клавишу.
- Структурированные ошибки обязательного входа, пустого/отсутствующего объекта.
- Счётчик, чтение после записи, чистота чтения, кеш одного действия, новые временные данные, разделение переменных объекта/игры/запуска.
- Условие выполняет выбранную ветку; числовой выход нельзя подключить к bool.
- Параметры/два результата функции, независимость вызовов, ID при переименовании; обязательность/типы аргументов и возврата.
- Ошибка результата до вызова; отсутствие return при заявленных результатах; ноль результатов.
- Явный объектный параметр функции, запрет рекурсии/вызова функции из функции.
- N=0/1/3/отрицательное/дробное, continue, break, return внутри цикла функции, запрет вложенных циклов/переходов области.
- Бюджет работы в вычислениях/функции и пустом цикле.
- История создания, удаления, преобразования, переменных и связей; сохранение ID, отмена поддерева, очистка redo и предел истории.
- Повреждённый/неподдерживаемый файл; искусственный отказ атомарной замены не повреждает предыдущий файл.
- Qt-интеграция: открытие/возврат панелей, запрет float, единственное игровое окно, остановка и reset.
- Создание базовой цепочки обработчиками UI, реальное редактирование поля карточки, клики по портам, drag объекта и одна запись undo.
- Создание одной переменной диалогом из карточки, undo/redo; создание сигнатуры и программы функции/цикла через обработчики и реальные диалоги редактора.
- Сохранение/повторная загрузка UI-программы и её запуск; навигация к карточке тела; динамическая ошибка не закрывает редактор.
- Сохранение/запуск сразу после редактирования поля не теряет отложенную правку; F5 и горячие клавиши документа не перехватывают ввод текста.

Автоматический UI-тест вызывает часть обработчиков напрямую и симулирует часть событий мыши/клавиатуры. Это не то же самое, что полностью ручная сборка обоих графов школьником.

## Windows-сборка

Первый реальный CI-прогон: Linux прошёл, Windows обнаружил ошибку **в тесте**, который читал русский JSON системной кодировкой cp1252. В тесте явно указана UTF-8; само приложение уже использовало UTF-8 при чтении/записи. Это исправление не скрывает проблему переменной окружением, а делает проверку переносимой. После исправления исходники прошли 67 тестов в реальном Windows CI (Python 3.12) и Linux CI (Python 3.13). Более поздний тест защищает клавиатурный ввод от горячих клавиш редактора; итоговый локальный набор — 68 проверок. Статус сборки и следующего прогона нужно смотреть у соответствующего коммита.

`check-build.yml` запускает тесты Windows Python 3.12 и Linux Python 3.13, затем собирает Windows onedir через PyInstaller. ZIP включает exe, Qt-библиотеки/плагины, документацию, примеры, лицензионные тексты и BUILD.txt. Истина о конкретном запуске CI — его статус и артефакты на GitHub, не сам факт наличия YAML.

Здесь **не выполнены** интерактивный запуск EXE без установленного Python, проверка зависимостей на чистой Windows, полный ручной прогон A/Б и всех диалогов. Даже успешно полученный ZIP не снимает эти пункты.

Ожидаемый ZIP: `dist/Horo-0.1.0-Windows-x64.zip`, preview release `v0.1.0-preview` при успешном workflow ветки `version/0.1`. Не извлекайте один EXE отдельно: папка `_internal` обязательна. В BUILD.txt записан точный исходный commit бинарника.

## Что означает «реализовано»

Функция имеет действующую модель, обработчики/исполнение и не заменена заглушкой. Автоматическая проверка означает конкретный пройденный тест. Ручная проверка означает реальный ручной сценарий. Windows EXE-проверка означает запуск соответствующей сборки на Windows. В этой поставке эти статусы не подменяют друг друга.

Известные ограничения языка/редактора перечислены в README. Внешние ожидания, таймеры, параллельность, вложенные циклы, глубокие вызовы, физика, экспорт игр и Android сознательно не входят в 0.1.
