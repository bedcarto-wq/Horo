# Протокол проверок Horo 0.2.0

## Исходная точка и сохранение регрессий

База: `056caed0a45c19aab0b3b75a9545b138c9e6fe2f`, ветка `version/0.1`. До правок **68 тестов прошли** в Linux с Qt offscreen.

Системные GL/EGL/xkbcommon для Qt были восстановлены в среде; первоначальная ошибка загрузки libGL относилась к отсутствующей системной библиотеке, не к регрессии исходников.

Из 68 прежних проверок 66 сохранены с прежними ожиданиями. Две отрицательные проверки локальных ограничений 0.1 обновлены по согласованному этапу: вложенный корректный цикл теперь допустим; вложенные calls допустимы, но рекурсия всё ещё отвергается. Прежние тесты не удалялись для сокрытия ошибки. Исходный набор/код доступны в базовом коммите.

Побайтово с базой совпадают `storage.py`, `history.py`, `ui/scene.py`, `ui/dialogs.py`, `requirements.txt` и `requirements-dev.txt`. Первые девять проектов не перегенерированы и не заменены. Открытие старого проекта не записывает его обратно автоматически.

## Локальная проверка 0.2.0

Среда: Amazon Linux 2023 x64, Python 3.13.14, PySide6 6.8.3, pytest 8.4.2, Qt offscreen. Модели времени используют управляемый clock, **без sleep и допусков реального времени**.

```bash
QT_QPA_PLATFORM=offscreen python -m pytest -q
```

Итоговый локальный набор: **113 passed**. Это проверки source, не ручная приёмка Windows EXE. Временные копии системных Qt-библиотек использованы только в компьютерной среде тестирования и не являются зависимостью/файлами репозитория.

### Новые проверки реальных графов

- Start один раз на экземпляр/новую игру; начальные значения уже доступны.
- Frame/time/delta, key release, несколько стартов, отдельные данные повторных запусков; нельзя подставить данные другого старта.
- Wait не раньше срока/не повторяется/не блокирует соседнюю ветку; sleep не расходует активный бюджет; 0 уступает update; отрицательные/NaN/inf/нечисловые значения ошибочны.
- Cancel/stop идемпотентны, удаляют ready/sleeping/owned contexts; новый сеанс не получает старые действия.
- Sequence ждёт все дочерние ветки; fork работает независимо, а repeat ждёт весь fork перед следующей итерацией.
- Пустые выходы завершаются; перестановка/удаление, сериализация и History сохраняют портовые ID/связи.
- While false=0, несколько актуальных проверок, ожидание, вложенные циклы. Repeat читает N один раз, даже если тело меняет переменную N.
- Break/continue отменяют только текущую итерацию; inner break не отменяет внешнего ожидающего соседа; функция не управляет чужим циклом.
- Поведение → А → Б с wait, отдельная цепочка работает сейчас; два вызова не смешивают параметры, temporary и результаты.
- Run-переменные общие между ветками одного запуска, отдельные между двумя событиями.
- Прямая/косвенная рекурсия; защищённая глубина; **64 допустимых вызова** проходят без рекурсивного Python-стека.
- Первый исполненный return выигрывает, завершённые изменения мира не откатываются; отменяются только потомки своего вызова.
- Нет return: ошибка только после всех листьев; return в цикле завершает функцию; вызов с wait внутри caller loop не теряет его контекст.
- Empty while(true), суммарный бюджет fork и live-task лимит frame→wait: ошибка со stop, не молчаливый пропуск.
- Ошибка глубокой ожидающей функции содержит её исходный node/graph и объект.
- Старые проекты с отсутствующим outputs и новые проекты дают корректный round trip; источник часов конечный/монотонный.
- Все девять новых файлов открываются, валидируются и исполняются на fake clock; выполнение не переписывает исходный JSON.

### Qt-интеграция

- Прежние панели/сцена/клавиша/игровое окно/сохранение/история/консоль и защита полей от shortcut проходят.
- Новые реальные кнопки выходов, стабильность связей, undo удаления, вложенная навигация назад/удаление/восстановление тела.
- Update меняет объект; repaint без update не создаёт frame-событие.
- Закрытие игры с wait очищает tasks/scopes/ready/sleepers.
- Несколько key-карточек и key release работают в игровом окне; полученное non-autorepeat keyUp является событием даже если старое keyDown было вне этого окна.

## Визуальная проверка

Просмотрены снимки source/offscreen интерфейса: sequence/fork с кнопками выходов и вложенное тело repeat. Сохранены тема, красные/синие порты, существующие панели и поля карточек. Это просмотр изображений Linux, не полный ручной drag/игровой плейтест Windows.

## Windows CI и сборка

Workflow проверяет source на Windows Python 3.12 и Linux Python 3.13, затем PyInstaller строит редактор. Ожидаемый результат: `Horo-0.2.0-Windows-x64.zip`, prerelease `v0.2.0-preview` при успешном запуске ветки `version/0.2.0`.

**Конкретный результат CI подтверждается его отчётом на GitHub, не наличием YAML.** В описании PR/итоговом сообщении указываются фактический успешный run и сборка после выполнения CI. BUILD.txt в ZIP указывает точный исходный commit.

## Что остаётся вручную

Не выполнены здесь:

- Интерактивный запуск именно Windows EXE на чистой Windows без Python.
- Полная ручная сборка всех новых графов, drag панелей/поля/диалоги save-discard-cancel на Windows.
- Весь чек-лист `TIME_GRAPH.md` из source и из Windows ZIP, включая остановку в ожидании и игру при потере фокуса.

Автоматические тесты/сборка/проверка состава архива не подменяют эти пункты. Статусы «реализовано», «автоматически проверено», «визуально просмотрено», «вручную Windows EXE» различаются.

## Известные границы

10 000 шагов/update, 1024 живые задачи (включая ожидающие контроллеры), 64 calls, запрет рекурсии/обратных проводов. Нет pause/time-scale, условных стартов, прогресс-save, физики, экспорта игр, Android, debugger и Print. Очень большие графы/сцены не оптимизированы; таймер 16 мс не гарантирует точные 60 FPS.
