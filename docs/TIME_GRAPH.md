# Horo 0.2.0: проверочные графы и ручная приёмка

## Быстрый сценарий: одна ветка ждёт, другая работает

Откройте `examples/time_parallel_sequence/project.horo.json`. Space:

1. Первая ветка разветвителя ждёт 1 секунду, затем сдвигает изображение на [60,0].
2. Вторая сразу сдвигает на [0,30].
3. Только после полного окончания обеих «Последовательно» запускает второй выход: [0,50].

Начальная позиция [80,100]. Сразу после нажатия [80,130], после ожидания [140,180]. Нажмите Space снова до окончания ожидания: это второй независимый запуск, не переиспользование первой цепочки.

### Как собрать самостоятельно

1. Поведение с key. Добавить sequence и fork.
2. key.next → sequence.in; sequence.1 → fork.in.
3. fork.1 → wait.in (N=1); wait.next → moveA.in.
4. fork.2 → moveB.in; sequence.2 → moveC.in.
5. Для каждого move подключить key.object и отдельный Vector2 с приведённым смещением.
6. Не соединять выходы move между ветками и не добавлять узел «объединить»: завершение группы учитывается Runtime.
7. Сохранить, закрыть/открыть, повторить. Вызвать undo/redo добавления выхода, перестановки и удаления связи.

## Узлы и поля

- **При старте:** срабатывает один раз на экземпляр в новой игре.
- **Каждый кадр:** срабатывает на игровой update, выдаёт время сеанса и delta в секундах.
- **При отпускании клавиши:** тот же выбор клавиши, что у key; автоповтор отбрасывается.
- **Ждать N секунд:** число через синий вход или поле; 0 уступает следующий update, отрицательное значение — ошибка.
- **Последовательно/Разветвитель:** минимум два выхода; кнопки +/↑/↓/× редактируют их стабильные ID и порядок. Обычные красные выходы остаются односвязными.
- **Пока:** bool-проверка перед каждой итерацией, «Открыть тело» как у repeat. Внутри тела разрешены вложенные repeat/while.
- **Call:** функция может вызвать функцию. Параметры/результаты передаются явно; объект также передаётся параметром, если нужен.

Несколько стартов добавляются через существующий поиск/категории. Не подключайте данные одного стартового узла к цепочке другого: Runtime не угадывает чужое событие.

## Дополнительные проекты

| Папка | Проверка |
| --- | --- |
| `time_events` | При старте +20 по X; каждый update двигает по X на delta (1 единица/сек); отпускание Space +20 по Y |
| `time_while` | «Осталось» начинается с 3; пока >0: уменьшить, ждать .5 с, сдвинуть +20; итог +60 |
| `time_break` | Fork в теле: запись и break отменяют ожидающую ветку; «Осталось»=2, позднего перемещения нет |
| `time_continue` | Запись и continue отменяют ожидание каждой итерации; счётчик доходит до 0 без позднего перемещения |
| `time_nested_functions` | Space: поведение → А → Б ждёт 1 с и возвращает Vector2 и число; repeat дважды двигает на [60,0]. Во время ожидания A (клавиша) двигает по Y на 20 |
| `time_nested_loops` | repeat 2 → repeat 3 → wait .2 → +10 по X; итог +60, две области тела сохраняются |
| `time_function_return` | Две ветки функции ждут .5 и 3 с; первый return возвращает [20,0] и отменяет второй [200,0]; позднего скачка нет |
| `time_task_limit` | Каждый update создаёт wait(1000); примерно после 1024 событий игра остановится с понятной ошибкой, не исчерпает память |

Это редактируемые модели, не заранее запрограммированная логика запуска. Старые 9 проектов остаются в examples и проверяются как прежде. Генератор новых: `python scripts/generate_time_examples.py`; не вызывайте его поверх вручную изменённых примеров, если хотите сохранить изменения.

## Вложенные тела

Откройте тело внешнего repeat/while, добавьте внутренний цикл, откройте его тело. Breadcrumb показывает путь; кнопка «Внешний граф» возвращает **на один уровень**. Корневые данные и данные предков показаны слева, их синие выходы доступны. Редактировать источник нужно в его собственной области.

Конец тела завершает итерацию. Break/continue действуют на ближайший цикл, а не на все циклы игры. Return внутри функции завершает весь конкретный вызов, даже если находится в глубоком теле.

## Обязательная ручная проверка

Провести сначала из source, затем в Windows EXE:

- Создать, а не только открыть, несколько стартов и граф параллельного ожидания.
- Проверить пустой выход sequence/fork: он пропускается как завершённая ветка.
- Переставить выходы с подключёнными линиями; они должны остаться привязаны к тем же ID, но выполняться в новом порядке.
- Удалить подключённый третий выход и отменить: вернуть ID/линию/порядок.
- While с ожиданием видит актуальный счётчик; первоначально false не запускает тело.
- Вложенный break не отменяет соседнюю ветку внешней итерации.
- Return отменяет собственные ожидания, не другой вызов функции.
- Остановить игру во время ожидания и запустить снова: старый move не появляется.
- Вызвать отрицательное N, рекурсию и превышение лимита; игра остановлена, редактор открыт, консоль ведёт к правильному узлу/области.
- Сохранить/загрузить и повторить; открытие проекта само по себе не переписывает файл.
- Повторить базовые проекты 0.1, панельные операции, импорт PNG, transform и undo.

Полная ручная Windows-приёмка не подменяется успешными unit/Qt-offscreen тестами или фактом сборки ZIP.
